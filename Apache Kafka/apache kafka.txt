Apache Kafka Core Architecture

Apache Kafka follows a distributed architecture where producers send messages to Kafka, Kafka stores them in topics, and consumers read those messages.

High-level architecture

                  │   Producer    │
                  └───────┬───────┘
                          │
                          │ Message
                          ▼
                ┌───────────────────┐

Main components
Producer
Sends messages/records to Kafka.
The producer decides which topic receives the message.
It can also influence which partition receives the message.
Broker
A Kafka server.
Receives, stores, and serves messages.
A Kafka cluster consists of multiple brokers.
Cluster
A group of Kafka brokers working together.
Provides scalability, fault tolerance, and high availability.

Topic

A logical category/name used to organize messages.
Example:
orders
payments
customers

Partition

A topic is divided into partitions.
Partitions allow Kafka to distribute data across brokers and process data in parallel.
orders
├── Partition 0
├── Partition 1
└── Partition 2

Replica

A copy of a partition stored on another broker.
Replication protects data if a broker fails.
Broker 1 → Partition 0 (Leader)
Broker 2 → Partition 0 (Replica)
Broker 3 → Partition 0 (Replica)
Consumer
Reads messages from Kafka.
Consumers normally read from one or more partitions.

Consumer Group

A group of consumers working together.
Within a consumer group, a partition is normally processed by one consumer at a time.
Topic: orders

Partition 0 ──→ Consumer 1
Partition 1 ──→ Consumer 2
Partition 2 ──→ Consumer 3

Offset

A unique sequential position of a record within a partition.
Consumers use offsets to track their reading position.
Partition 0

Offset: 0    1    2    3    4

The important relationship

Think of Kafka like this:

Kafka Cluster
      │
      ├── Broker 1
      │      ├── Topic A
      │      │    ├── Partition 0
      │      │    └── Partition 1
      │      └── Topic B
      │
      ├── Broker 2
      │      └── Topic A
      │           ├── Partition 0 Replica
      │           └── Partition 1 Replica
      │
      └── Broker 3
             └── ...

Interview summary:

Producer → Topic → Partition → Broker → Consumer Group → Consumer

And the two concepts that provide reliability and scalability are:

Partitions → scalability & parallelism
Replication → fault tolerance & high availability
